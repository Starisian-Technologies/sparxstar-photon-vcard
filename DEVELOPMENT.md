# Development Guide

This document covers everything you need to get a local development environment running for **SPARXSTAR Photon VCard**.

---

## Requirements

| Tool | Minimum version |
|------|----------------|
| PHP | 8.2 |
| WordPress | 6.8 |
| Composer | 2.x |
| Node.js | 20 LTS (24 used in CI) |
| npm | 10+ |

Optional but recommended:

- [Local by Flywheel](https://localwp.com/) or [wp-env](https://developer.wordpress.org/block-editor/reference-guides/packages/packages-env/) for a containerised WordPress environment
- [Advanced Custom Fields (ACF)](https://www.advancedcustomfields.com/) or [Secure Custom Fields (SCF)](https://wordpress.org/plugins/secure-custom-fields/) to exercise ACF-dependent features

---

## Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/Starisian-Technologies/sparxstar-photon-vcard.git
cd sparxstar-photon-vcard

# 2. Install PHP dependencies (PHPCS, PHPStan, and their standards)
composer install

# 3. Install Node.js dependencies (build tools, linters)
npm ci

# 4. Run all linters and static analysis to verify the baseline
npm test
```

Then symlink (or copy) the repository root into your local WordPress `wp-content/plugins/` directory and activate the plugin from **Plugins → Installed Plugins**.

## Build Commands

| Command | Description |
|---------|-------------|
| `npm run build` | Minify both CSS and JS into `assets/` |
| `npm run build:css` | Minify CSS only |
| `npm run build:js` | Minify JS only |

> **Note:** Minified files (`assets/css/*.min.css`, `assets/js/sparxstar-photon-vcard.min.js`) are git-ignored and generated by CI during the release workflow. Never commit them manually.

## SCRIPT_DEBUG Mode

When `SCRIPT_DEBUG` is defined and truthy in `wp-config.php`, the plugin enqueues the **unminified source files** from `src/css/` and `src/js/` directly:

```php
// wp-config.php
define( 'SCRIPT_DEBUG', true );
```

This is the recommended setting for local development; it provides readable stack traces and source maps.

In production (`SCRIPT_DEBUG` false or undefined), the plugin loads the minified assets from `assets/`.

## ACF Setup

The plugin registers its ACF field group automatically via `acf/include_fields`. No manual field creation is required. To test the card:

1. Install and activate ACF or Secure Custom Fields.
2. Navigate to **Users → Your Profile** in WP Admin.
3. Fill in the "User Details" fields that appear.
4. Set **Display Business Card** to `true`.
5. Visit any public-facing page — the business card overlay should be available.

---

## Testing Locally

There is currently no automated PHP unit-test suite. Manual testing steps:

1. Enable `SCRIPT_DEBUG` for readable output.
2. Activate the plugin and verify the admin notice appears.
3. Set ACF card fields on a user and navigate to a public page.
4. Test all trigger methods: shortcode button, `Shift+V`, long-press.
5. On a mobile device: test the "Enable Motion Trigger" button, then test shake and flip triggers.
6. Verify the `.vcf` download and Web Share API flows.
7. Test deactivation (no JS errors) and deletion (options + user meta removed).

## Release Process

Releases are fully automated via the `build-release.yml` workflow:

1. Create and push a semver tag: `git tag v0.6.0 && git push origin v0.6.0`
2. CI will:
   - Update version numbers in PHP headers and README
   - Minify CSS and JS
   - Package a distributable `.zip` (without `node_modules`, `src/css`, `src/js`, `package.json`)
   - Generate a SHA256 checksum
   - Create a GitHub Release with the archive and checksum attached

Do **not** manually update version strings — the release workflow handles that.
